# Sub2API Taskbar Dashboard

## Назначение и текущее состояние

Новый самостоятельный проект мода Windhawk для Windows 11. Сейчас здесь только
документация и настройки исключения локальных файлов. Production-кода нет.
Не считать исходники соседнего проекта реализацией этого проекта.

## Навигация и границы

- `README.md` — назначение, фактический статус и навигация.
- `Documentation/Business logic/` — согласованные будущие требования.
- `Documentation/Technical documentation/` — проверенные факты исходного мода
  и API sub2api, ограничения и ссылки на владеющие исходники.
- `Documentation/Plans/initial-implementation-2026-11-04-(not-started)/` — этапы,
  подэтапы, зависимости, критерии и открытые вопросы.
- `../windhawk-codex-lb-taskbar-dashboard/` — эталон внешнего вида, только источник
  для будущей адаптации; `../sub2api/` — источник контрактов сервера.

Текущий запрос разрешает создать проект и документацию, но не реализовывать мод.
Не менять соседние проекты и глобальные инструкции. Git-операции, в том числе
`git init`, требуют отдельной просьбы о соответствующей операции.

## Правила будущей реализации

Сохранять внешний вид исходного мода. Данные — только OpenAI; сводное значение —
средний остаток недельного лимита. Не подменять его денежным балансом ключа,
месячным процентом или данными другой платформы. Не принимать предлагаемые
варианты из открытых вопросов за утверждённые требования.

Предлагаемая структура C++: `mod.wh.cpp` как точка входа, `src/` с заголовками
одной единицы трансляции, `tests/` с изолированными проверками, необязательный
`editor/`. Создавать эти папки вместе с реальным содержимым и локальным
`AGENTS.md` в соответствующем подэтапе. Не создавать solution или отдельную
систему сборки без необходимости.

Независимые ID мода, namespace, имена окон, mutex и кешей должны позволять
сосуществовать с исходным модом. Не переносить реальные адреса, ключи,
логин/пароль, машинные настройки и файлы `.git`/`.vs` из соседнего проекта.

Секреты не сохранять в документах, fixtures или логах. Для диагностики использовать
краткие английские сообщения с кодом/статусом и безопасными идентификаторами;
не логировать целиком административные ответы, credentials и заголовки авторизации.
Транспорт/авторизация, частичные ошибки, отмена и освобождение ресурсов должны
иметь проверяемое поведение, без маскировки неизвестных данных под успешный результат.

## Документы и проверки

Изменять файлы только в разрешённом объёме; ручные правки — через `apply_patch`.
Для новых текстов использовать UTF-8 без BOM; сохранять установившиеся окончания
строк. Проверять кириллицу, U+FFFD и четыре вопросительных знака подряд.
Обновлять навигацию, затронутые требования и статусы подэтапов/этапов вместе
с разрешённой работой. Обновлять локальные инструкции при изменении ответственности
папок; не вести в них отдельный реестр выполнения.

Не запускать проектные скрипты, компилятор C++, тестовые executable, Windhawk,
Explorer или сетевые проверки без отдельного разрешения на точную команду и файл.
Приведённый в плане способ проверки сам по себе не разрешает запуск.
Не подключаться к БД и не выполнять SQL. Статическая проверка документов
не подтверждает сборку, работу мода или визуальную приёмку.
