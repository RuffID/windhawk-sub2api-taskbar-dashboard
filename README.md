# Sub2API Taskbar Dashboard

Мод Windhawk для Windows 11: средний остаток недельного лимита
OpenAI-аккаунтов sub2api на панели задач и подробности в popup.

Состояние на 04.11.2026: поверх независимой основы этапа 02 реализованы
03.01–03.03. Подключены все страницы OpenAI-аккаунтов, прямые quota-запросы,
нормализация и средний недельный остаток. Taskbar и popup используют один snapshot;
неполный результат помечен `*`, в popup есть счётчик полноты и состояние данных.
В этапе 04 подключены карточки с отдельной строкой качества данных, доступные
окна, Reset, версии сервера и независимая проверка релизов GitHub с отдельным
часовым кешем. Сборка, fixtures и работа мода не проверены; выполнен только
статический разбор. Этапы 03/04 ожидают обязательных проверок запуском.
Git уже инициализирован; существующая .git сохранена, Git-команды не выполнялись.

Уточнение 05.11: пользователь подтвердил базовое отображение аккаунтов прежней
сборкой. Добавлены примеры внутри полей настроек и необязательный GitHub-токен.
Эта новая правка проверена только статически; компиляция и fixtures не запускались.
Остальные проверки этапов 03/04 остаются открытыми, этап 05 не начат.

Внешний вид и взаимодействия должны соответствовать
[исходному проекту](../windhawk-codex-lb-taskbar-dashboard/README.md): карточки
аккаунтов, цвета, прозрачность, сроки сброса, количество Reset, версии и ссылки.
Область данных ограничена OpenAI. Процент — среднее арифметическое остатков

## Подключение

Для виджета выбран администраторский API-ключ sub2api. Он вводится
непосредственно в поле «Администраторский API-ключ» настроек модификации Windhawk.
В полях сразу показаны примеры `https://sub2api.example.com` и
`YOUR_SUB2API_ADMIN_KEY`, как начальные значения в исходном моде.
Замените их своими значениями; примеры и пустые поля не вызывают запросов.
Существующие сохранённые значения сохраняются. Логин, пароль и переменные
окружения не требуются.
Допускаются полный и ограниченный администраторские ключи. После чтения
квоты полным ключом sub2api ставит аккаунт в очередь проверки: если автосброс уже
включён и его условия выполнены, сервер может потратить Reset и восстановить лимит.
Такое поведение допустимо. Ограниченный ключ этой проверки не инициирует.
Для ограниченного ключа нужны `accounts.read`, `accounts.identity.read`, `openai.quota.read` для нужной
области OpenAI OAuth и глобальное `system.read` для версии сервера.
Это права локального исходного дерева sub2api. В опубликованном 0.2.19
ограниченный `adm_sc_` не имеет доступа к quota даже со всеми галочками;
пользователь подтвердил HTTP 200 для quota с прежним полным ключом.
В поле «Адрес sub2api» задаётся базовый HTTP(S) адрес, включая необязательный
префикс reverse proxy, без `/api/v1/admin`, query, fragment, логина и пароля.
Пустой адрес/ключ или оставленный пример запрещает отправку.
Транспорт поддерживает `x-api-key` и стандартный ответ sub2api; login/cookie
codex-lb не перенесены. Настройки меняются после отмены и завершения старых
обновлений. Таймаут и общий deadline ограничивают запросы, размер ответа — 4 MiB;
редиректы, cookies и автоматическая авторизация отключены.
Аккаунты читаются только GET списка и прямого quota. Параллельных
quota-запросов не больше четырёх; общий deadline относится ко всему обновлению.
Версии читаются отдельной операцией: два административных GET и публичные
релизы `Wei-Shaw/sub2api`, включая prerelease. Ключ sub2api в GitHub не передаётся.
Версии не задерживают публикацию аккаунтов и не меняют время их успешного чтения.
Ошибка проверки видна отдельно и не означает «Нет новых версий».
GitHub-кеш нового мода и межпроцессный mutex сохраняют минимум час между
проверками; Retry-After/rate limit продлевают ожидание. Ручное обновление и
reload паузу не обходят. Значок обновления taskbar берётся из has_update сервера.

Необязательное поле «GitHub-токен» принимает отдельный Personal Access Token
GitHub без `Bearer` и кавычек. Пример `YOUR_GITHUB_TOKEN_OR_LEAVE_EMPTY` или пустая
строка означают анонимный режим. Для публичных релизов достаточно fine-grained
токена с доступом к публичным репозиториям без дополнительных прав записи.
Создание: GitHub Settings → Developer settings → Personal access tokens →
Fine-grained tokens → Generate new token → Public repositories (read-only).
Токен вводится только в настройках Windhawk, в чат/исходники его не копировать.
Он отправляется только `api.github.com`; административный ключ остаётся в sub2api.
GitHub обычно разрешает 60 анонимных запросов в час на IP и 5000 с PAT на пользователя,
но дополнительные ограничения сохраняются ([лимиты GitHub](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api),
[создание токена](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)).
Смена токена не сбрасывает уже сохранённую паузу; «Лимит GitHub» может оставаться
до следующей разрешённой проверки. Проверка мода по-прежнему не чаще раза в час.

Числовой «Возраст» в карточке скрыт по просьбе пользователя. Свежесть по серверному
`fetched_at` продолжает проверяться отдельным таймером без HTTP: значение старше
15 минут исключается из недельного среднего, в карточке остаётся «Устарело».

## Анализ кода в редакторе

Локальная [конфигурация clangd](.clangd) использует `editor/compile_commands.json`.
База содержит пути этого компьютера, исключена из Git и описывает исходник
проекта и его копию в редакторе Windhawk. Правила — в [editor/AGENTS.md](editor/AGENTS.md).
05.11.2026 общая `.clangd` в `D:/Programs/Windhawk/AppData/EditorWorkspace`
переключена с базы исходного Codex LB-мода на базу этого проекта.
В открытом редакторе нужно нажать `Ctrl+Shift+P` и выполнить
`clangd: Restart language server`. При переходе к другому моду общую `.clangd`
нужно переключить на его базу: автоматического выбора по `@id` нет.
Пути и флаги проверены статически; исчезновение сообщений анализатора
и успешность компиляции этим не подтверждены.

## Дальнейшая работа

Правила согласованы: все доступные группы OpenAI, отключённые/неработающие записи
исключаются из среднего, одна подписка учитывается один раз. Среднее считается
по известным значениям не старше 15 минут с признаком неполноты, округляется
только итог. Релизы берутся из официального `Wei-Shaw/sub2api`.

Контракты статически проверены. Отдельный значок и сообщение о необходимости
переавторизации в мод не входят; общие статусы и ошибки сохраняются.
Подтверждение внешней среды остаётся для будущей приёмки.
Новый мод имеет отдельные идентификаторы и учитывает ширину исходного виджета.
Значок GitHub рядом с версией мода открывает
[репозиторий мода](https://github.com/RuffID/windhawk-sub2api-taskbar-dashboard).
Этапы 01–02 завершены; реализация этапа 03 готова, проверки запуском остаются
открытыми. 04.01/04.02 реализованы, этап 04 имеет статус verification:
сборка, новые fixtures и визуальная приёмка не выполнены. Этап 05 не начат.
После реализации 04 работа остановлена.
Компиляция, fixtures, транспортные тесты, доступ к
серверу, визуальное соответствие, DPI, reload/unload и сосуществование модов
требуют отдельных разрешений и остаются для этапа 05.

Инструкция установки появится после подготовки и проверки работающего мода.
