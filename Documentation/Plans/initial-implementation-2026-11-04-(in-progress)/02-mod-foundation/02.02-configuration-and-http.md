# 02.02. Настройки и HTTP-доступ

Статус: completed

## Цель и результат

HTTP-клиент sub2api с согласованной авторизацией, настройками адреса и предсказуемой
отменой, пригодный для последующего загрузчика аккаунтов.

## Зависимости и границы

02.01 и проверенные права/контракты 01.01. Полный или ограниченный администраторский
ключ задаётся прямо
в настройках Windhawk. Не читать и не менять конфигурацию Codex Desktop
или пользовательские переменные окружения ради подключения.

## Затрагиваемые части и работы

- [x] Адаптировать `src/config`, `src/network` и модель настроек: адрес,
  поле `adminApiKey` («Администраторский API-ключ») с пустым значением по умолчанию,
  interval и timeout, без встроенного реального сервера.
- [x] Читать ключ через API настроек Windhawk, не отправлять запрос при пустом
  значении и не выводить ключ в popup или диагностические сообщения.
- [x] Поддержать заголовок `x-api-key`, базовый путь и стандартный
  envelope sub2api; исключить перенос dashboard-cookie/login codex-lb.
- [x] Сохранить единый snapshot настроек для обновления, общий deadline,
  отмену при смене настроек/unload и ограничение размера ответа.
- [x] Добавить безопасную диагностику отказов: английское событие, статус/код,
  без заголовков авторизации, cookie, credentials и полного ответа.
- [x] Обновить локальные инструкции и техническую документацию настроек.

## Проверки и критерии готовности

- [x] Статически разобраны пустой ключ, неверный URL, HTTP 401/403/429/5xx,
  не-JSON и повреждённый envelope; отказ не считается успешным обновлением.
- [x] GitHub-запросы не получают sub2api-ключ или серверные cookies.
- [x] Описание поля ключа допускает полный и ограниченный режимы, перечисляет
  необходимые для ограниченного ключа права
  `accounts.read`, `accounts.identity.read`, `openai.quota.read`, `system.read`;
  префикс ключа не используется как доказательство выключенного full_access.
  Серверная проверка автосброса после чтения полным ключом допустима;
  клиент не меняет настройки автоматики и не вызывает отдельные операции сброса.
- [x] Смена ключа в настройках отменяет старые запросы; последующее обновление
  использует новый ключ, а результат отменённого запроса не публикуется.
- [x] Повтор/отмена не оставляет незакрытый запрос или работу со старыми настройками.

Содержательные транспортные проверки со stub/локальным сервером планируются
в 05.01; запуск требует отдельного разрешения с указанием режима.

## Фактический результат

Добавлены sub2apiUrl/adminApiKey (оба пустые), interval=60 и timeout=30.
Без валидного подключения транспорт не отправляет административный запрос.
Sub2ApiGet использует x-api-key и /api/v1/admin с сохранением reverse-proxy
префикса; ожидает HTTP 2xx и envelope code=0/message:string/data:object.
Полный и ограниченный ключи передаются одинаково, префикс не определяет права.
Клиентских вызовов сброса, его настройки, login/cookie и чтения credentials
из окружения нет. Срок запроса ограничивается timeout и общим deadline;
ответ ограничен 4 MiB, UTF-8 проверяется строго. Redirects/cookies/auto-auth
выключены, отдельный GitHub-вход не принимает ключ и имеет фиксированный URL.

Статически разобраны пустое подключение/неверный URL, 401/403/429/5xx, non-JSON,
повреждённый envelope, ненулевой code, предельный размер и отмена во всех ожиданиях.
Смена настроек сигнализирует отмену и дожидается старых callbacks до замены
snapshot и сброса события. Отказ/отмена не публикует ответ как успешные данные.
Логи содержат только английское событие и status/HRESULT; тело/message/key
не выводятся. Runtime пока не вызывает транспорт и не ставит время успеха.

Компиляция и транспортные тесты не запускались. Фактическая проверка timeout,
deadline, размера, отмены, обоих ключей и URL с префиксом остаётся в 05.01/05.02.
