### Реализация и статическая проверка до приёмки


Два административных GET читаются по фактическому контракту; непустой warning
не выдаётся за успех. Taskbar использует только серверный has_update.
Независимая GitHub-проверка включает prerelease, сохраняет исходный tag и
экранирует его как URL-сегмент. Полный/ограниченный ключи не различаются префиксом.
Pending/Unknown/Failed/RateLimited/актуальность/обновление видимы раздельно.

Persistent cache и mutex имеют отдельные имена Sub2ApiTaskbarDashboard.
Резервация сохраняется до запроса и завершается при отмене/исключении с
сохранением часовой паузы; более поздние Retry-After/Reset продлевают её.
Отдельный PTP_WORK ограничен по времени, drain происходит до reset/settings;
публикация проверяет generation/cancel. Критерий успеха аккаунтов не менялся.
Добавлен tests/popup_versions.cpp с production fixtures, временным кешем,
двумя клиентами, ошибками/отменой и ссылками. Сборка и запуск не выполнялись,
поэтому критерии проверок выше остаются открытыми. Реальных запросов не было.

Уточнение 05.11: по просьбе пользователя добавлено отдельное необязательное
поле GitHub PAT; адрес/ключ sub2api показывают безопасные примеры прямо в полях.
Примеры нормализуются в пустые значения. Bearer идёт только в api.github.com,
x-api-key — только в sub2api. Общий кеш/часовой минимум/Retry-After сохраняются
при смене токена. Production fixtures расширены проверками авторизации и паузы,
но не запускались; новая правка не скомпилирована. Пользователь подтвердил базовое
отображение прежней сборки, что не закрывает остальные критерии этапа.
