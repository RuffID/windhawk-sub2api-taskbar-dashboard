# 02.02. Настройки и HTTP-доступ

Статус: not-started

[Этап](main.md) · [План](../main.md)

## Цель и результат

HTTP-клиент sub2api с согласованной авторизацией, настройками адреса и предсказуемой
отменой, пригодный для последующего загрузчика аккаунтов.

## Зависимости и границы

02.01 и проверенные права/контракты 01.01. Полный или ограниченный администраторский
ключ задаётся прямо
в настройках Windhawk. Не читать и не менять конфигурацию Codex Desktop
или пользовательские переменные окружения ради подключения.

## Затрагиваемые части и работы

- [ ] Адаптировать `src/config`, `src/network` и модель настроек: адрес,
  поле `adminApiKey` («Администраторский API-ключ») с пустым значением по умолчанию,
  interval и timeout, без встроенного реального сервера.
- [ ] Читать ключ через API настроек Windhawk, не отправлять запрос при пустом
  значении и не выводить ключ в popup или диагностические сообщения.
- [ ] Поддержать заголовок `x-api-key`, базовый путь и стандартный
  envelope sub2api; исключить перенос dashboard-cookie/login codex-lb.
- [ ] Сохранить единый snapshot настроек для обновления, общий deadline,
  отмену при смене настроек/unload и ограничение размера ответа.
- [ ] Добавить безопасную диагностику отказов: английское событие, статус/код,
  без заголовков авторизации, cookie, credentials и полного ответа.
- [ ] Обновить локальные инструкции и техническую документацию настроек.

## Проверки и критерии готовности

- [ ] Статически разобраны пустой ключ, неверный URL, HTTP 401/403/429/5xx,
  не-JSON и повреждённый envelope; отказ не считается успешным обновлением.
- [ ] GitHub-запросы не получают sub2api-ключ или серверные cookies.
- [ ] Описание поля ключа допускает полный и ограниченный режимы, перечисляет
  необходимые для ограниченного ключа права
  `accounts.read`, `accounts.identity.read`, `openai.quota.read`, `system.read`;
  префикс ключа не используется как доказательство выключенного full_access.
  Серверная проверка автосброса после чтения полным ключом допустима;
  клиент не меняет настройки автоматики и не вызывает отдельные операции сброса.
- [ ] Смена ключа в настройках отменяет старые запросы; последующее обновление
  использует новый ключ, а результат отменённого запроса не публикуется.
- [ ] Повтор/отмена не оставляет незакрытый запрос или работу со старыми настройками.

Содержательные транспортные проверки со stub/локальным сервером планируются
в 05.01; запуск требует отдельного разрешения с указанием режима.

## Фактический результат

Реализация не начата. Настройки и HTTP-клиент отсутствуют.
