# 03.02. Нормализация лимитов и статусов

Статус: not-started

[Этап](main.md) · [План](../main.md)

## Цель и результат

Единая модель карточки с именем, email, окнами остатка, временем сброса,
количеством Reset, сроками credits, статусом и качеством данных.

## Зависимости и границы

03.01 и правила 01.01–01.02. Использовать только разрешённые поля; не копировать
credentials или произвольный `extra` в модель и логи. Сброс квот не выполнять.

## Затрагиваемые части и работы

- [ ] Добавить типизированную нормализацию полного/ограниченного контракта на
  владеющей границе JSON, различая отсутствие, `null`, неверный тип и нулевой расход.
- [ ] Сопоставить окна по длительности/полям; преобразовать расход в остаток,
  отдельно сохранить недельное и месячное значение и метку времени snapshot.
- [ ] Для weekly требовать длительность 604800 секунд, для 5h — 18000;
  свежесть брать из quota `fetched_at`, а не времени HTTP/общего usage `updated_at`.
- [ ] Сохранить полную пару upstream account/user для устранения дублей в памяти,
  не выводя её в логи. Пропуск идентичности не заменять совпадением email/name.
- [ ] Сопоставить имя/email и достоверные состояния недоступности с моделью карточки.
  Отдельный флаг/диагностику переавторизации не добавлять: в согласованный
  объём входят только доступные общие статусы и ошибки.
- [ ] Вычислить ближайший известный срок доступных Reset credits; сохранить
  отдельность неизвестного количества и неизвестного срока.
- [ ] Обновить `src/core`/`src/accounts` инструкции и технический маппинг.

## Проверки и критерии готовности

- [ ] Fixtures различают 0% расхода, 100%, отсутствие данных и ошибку доступа.
- [ ] Есть окна 5h/7d/monthly, переставленные primary/secondary, неизвестная
  длительность, UTC/reset без timestamp, просроченный snapshot.
- [ ] Синтетическое нулевое окно общего usage и его новое `updated_at` не
  принимаются за достоверный свежий upstream-остаток; missing identity даёт неполноту.
- [ ] Reset с несколькими сроками показывает ближайший доступный; ошибка
  quota не обнуляет достоверный usage и не скрывается как успешное чтение.
- [ ] Renderer не делает HTTP и не разбирает сырой административный JSON.

Содержательные изолированные тесты должны вызывать production-парсер.
Реальная форма ответа развёрнутого сервера подтверждается отдельно в 05.02.

## Фактический результат

Реализация не начата. Нормализованной модели и парсера нет.
