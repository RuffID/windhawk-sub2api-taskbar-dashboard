Дата создания: 2026-11-04

## Цель и основание

Создать самостоятельный аналог Windhawk-мода codex-lb для sub2api, сохранив
внешний вид. Только OpenAI, на панели задач — средний остаток недельного лимита.
Основание: запрос и уточнения пользователя в текущем чате 04.11.2026.

Созданы документы и `.gitignore`; исходники не перенесены. Документальный этап 01
выполнен: правила согласованы, маршруты/проекции/побочные эффекты изучены статически.
Этапы реализации 02–05 не начинались. Git не инициализирован, программные и сетевые

## Требования и границы

Основной документ — [бизнес-требования](../../Business%20logic/requirements.md).
Подтверждённые внешние контракты — [техническое обследование](../../Technical%20documentation/integration.md).
Неопределённые решения — [открытые вопросы](open-questions.md).

Способ подключения определён: администраторский ключ sub2api вводится прямо
в настройках Windhawk. Допускаются полный и ограниченный ключи. Для ограниченного
ключа нужны ресурсные `accounts.read`,
`accounts.identity.read`, `openai.quota.read` и глобальное `system.read`,
при `full_access=false`. Серверная проверка уже включённого автосброса после
чтения полным ключом и возможный расход Reset допустимы;
использование ключа Codex Desktop и серверное расширение для него не планируются.

Текущий объём — только документация. Перенос C++, настройка доступа, компиляция,
запуски и установка требуют последующего поручения с соблюдением правил запусков.
Сервер sub2api и исходный мод не меняются. Собственная реализация автосброса,
его настройка, отдельные вызовы сброса, другие платформы и изменение сервера
не входят в план реализации мода. Штатная серверная автоматика может срабатывать
после чтения квоты полным ключом.

## Порядок выполнения и общая приёмка

Каждый этап имеет обзор и отдельные небольшие подэтапы. Можно выполнять подэтап
с готовыми зависимостями; разрешение на один не означает автоматический переход
к остальным. Статусы синхронизируются в файлах подэтапов и таблицах этапов,
затем в этом документе и имени папки плана при смене общего статуса.

Использовать согласованные правила состава среднего и подтверждённые права.
Не заменять лимиты аккаунтов денежной статистикой `/v1/usage` при отказе доступа.
Отдельный значок и сообщение переавторизации исключены из функциональности;
общие статусы и ошибки сохраняются. Оставшиеся сведения для внешней проверки
перечислены в открытых вопросах; они не означают незакрытый выбор формулы или GitHub-источника.

Для общего завершения нужны: корректный расчёт на согласованных данных,
изолированные проверки парсинга и отказов, сборка, подтверждённый доступ к
целевому серверу, визуальное соответствие и проверка жизненного цикла в Windhawk.
При отсутствии разрешения на запуск отмечать соответствующую проверку открытой,
не закрывать обязательную приёмку статическим чтением кода.
