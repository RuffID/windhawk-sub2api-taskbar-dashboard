# Аккаунты и недельное среднее

Реализация этапа 03 на 04.11.2026 проверена статическим чтением. Компилятор,
fixtures, HTTP, Windhawk и Explorer не запускались. [Контракты сервера](integration.md)
и [бизнес-правила](../Business%20logic/requirements.md) остаются основанием поведения.

## Поток и владение

[Runtime](../../src/integration/runtime.h) получает один snapshot настроек и один
deadline на весь refresh (`requestTimeoutSeconds`, по умолчанию 30 секунд).
[Загрузчик](../../src/accounts/pool.h) последовательно читает
`/accounts?platform=openai&page_size=100&page=N`: без group/status/type.
Полный ключ и ограниченный используют один код, без проверки префикса.
Отключённые, ошибочные и не-OAuth записи остаются в пуле для карточек.
Для всех обнаруженных OAuth-записей выполняется только прямой GET quota.
Нет вызова usage batch, POST refresh, reset, изменения аккаунтов или автосброса.
Допустимый серверный побочный эффект полного GET сохраняется.

Пагинация проверяет типы и согласованность page/page_size/pages/total/items.
Изменение total/page_size, повтор ID, повреждённая запись или отказ страницы
оставляют discovery неполным. Загрузчик продолжает известные последующие страницы
и расширяет обход при росте pages, пока позволяет общий deadline. Повтор локального
ID даёт одну карточку; конфликт status/schedulable делает их недостоверными.
Стабильный пустой ответ — полный пустой пул. Только полный обход подтверждает
удаление; при неполном обходе прошлые карточки сохраняются с ошибкой списка.
Offset pagination сервера не даёт атомарного снимка: перестановку записей при
неизменном total без повторов/пропусков доказать по этим метаданным невозможно.

До четырёх workers владеют quota-запросами. Результат записывается в запись
с заданным local ID, порядок завершения не используется. У каждого потока свой
WinRT apartment; RAII делает join всех созданных потоков и при частичной ошибке
создания. Отказ одного запроса не отменяет остальные. Общая отмена/дедлайн
останавливают выдачу работы, HTTP использует тот же deadline/cancel event;
возврат loader происходит только после завершения workers и HTTP contexts.

## Типизированная проекция

[Модели](../../src/core/account_data.h) сохраняют Missing/Null/Invalid/Value;
[парсер](../../src/accounts/parser.h) — единственная граница JSON. Из списка
читаются local ID, имя, platform/type, status/schedulable и email из явно
разрешённых credentials.email/extra.email. Из quota — полная account/user-пара,
email, fetched_at, два основных окна и Reset. JSON/credentials/extra целиком,
денежный credits и additional_rate_limits Spark не копируются в модель.
Сырые primary/secondary slots сохраняются как типизированные поля для диагностики
качества; именованные 5h/weekly/monthly определяются длительностью.

5h — 18000 секунд, weekly — 604800, monthly — 28–31 сутки, отдельно от weekly.
Неизвестная длительность не становится недельной. Два окна одной длительности
считаются неоднозначными. Отрицательный/нечисловой расход недостоверен, 0 расхода
даёт 100% остатка, расход >=100 даёт 0%. Нефинитные числа отвергаются.
Известный истёкший reset исключает окно; отсутствие абсолютного reset не создаёт
синтетического времени из HTTP или reset_after_seconds.

Reset count — отдельное целое поле, включая достоверный ноль; неизвестное поле
не превращается в ноль. Из credits выбирается ближайший известный будущий
expires_at в поддерживаемом UTC-формате, включая дробные секунды. Количество
и срок читаются независимо; неизвестный срок не скрывает известный count.
Ошибка/отсутствие Reset не отменяет пригодные лимиты. Upstream-пара остаётся
только в памяти расчёта и не передаётся карточке/логам.

## Пригодность, ошибки и публикация

[Расчёт](../../src/accounts/weekly.h) исключает status!=active и ручное
schedulable=false. Неизвестный статус остаётся неопределённой частью пула.
Не-OAuth или отсутствие weekly не заменяются месячной/денежной квотой.
Среди одинаковых полных account/user-пар выбирается наиболее свежий пригодный
snapshot, при равенстве — меньший local ID. Email/name для группировки не нужны.
Достоверно исчерпанное окно 0% учитывается. Среднее использует исходные дроби;
только итог округляется половиной вверх. Карточки округляют свои значения отдельно
для отображения и не участвуют этими округлёнными числами в среднем.

Возраст считается по исходному quota fetched_at; future/missing/invalid timestamp
не доказывает свежесть. В возрасте 899 и ровно 900 секунд значение допустимо,
в 901 — нет. Отказ quota или пропуск запроса из-за deadline может сохранить
предыдущую квоту того же local ID только в пределах возраста. При успешном
ответе вся проекция заменяется: пропавшие identity-права не восстанавливаются
из кеша. Неполный список не запускает обходные запросы к отсутствующим IDs.

Сводка хранит usable/expected. Expected объединяет известные полные пары,
неопределённые записи и известный по total остаток незагруженных записей.
При неизвестной идентичности или неполном discovery это оценка кандидатов:
`?` у знаменателя явно запрещает считать число точным количеством подписок.
Среднее известных пригодных значений имеет `*`; без пригодных данных — «Нет данных*».
Пустой полный пул — «Нет данных», 0/0, без деления на ноль.

[Publication gate](../../src/accounts/publication.h) проверяет cancel и поколение
настроек под g_dashboardMutex. Pause/unload под тем же mutex меняют поколение,
сигнализируют cancel, затем ждут сетевой и age timers/manual callbacks; только
после drain разрешена замена настроек/reset event. Отменённая работа и старое
поколение не публикуются. Истечение общего deadline даёт частичный результат,
если это не отмена настроек/unload. Один опубликованный pool порождает taskbar,
счётчик, базовые карточки и состояние ошибок. Отложенный taskbar dispatch читает
актуальный опубликованный текст, а не сохранённый текст старого callback.

Критерий обновления времени успеха: discovery полный, все запланированные OAuth
quota успешно прочитаны с пригодным fetched_at, каждая включённая подписка
представлена пригодной weekly-квотой, refresh не прерван. Полный пустой пул
допускается. Частичный отказ, недостоверные/старые данные и age timer время
успеха не меняют. Независимый timer раз в секунду пересчитывает возраст и
истечение известных окон без HTTP, даже при длинном интервале сетевых запросов.

В этапе 04 UI дополнен: `*` и измеренный счётчик подписок в заголовке,
краткий статус/ошибка/возраст в отдельной строке под reset. При отсутствии 5h
длинное окно занимает всю ширину; доступны weekly и monthly, при двух длинных
окнах видны оба. Monthly не подставляется в среднее. Сортировка использует
дробный остаток длинного окна (weekly предпочтительно), неизвестные — в конце.
[Версии и полная привязка карточек](popup-and-versions.md) не меняют loader/формулу.

Диагностика: Account discovery failed (page/status), Quota query failed
(local ID/status), Quota worker(s) failed/unavailable, Snapshot incomplete
(usable/expected/discovery при изменении состояния). Нет тел ответов, ключей,
email, имён и upstream IDs. Ключ не передаётся GitHub; версии подключены отдельно.
