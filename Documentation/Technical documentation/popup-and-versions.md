## Отображение данных

[Проекция аккаунтов](../../src/accounts/presentation.h) использует существующий
snapshot и расчёт среднего. Карточки показывают name/email, доступные 5h и
weekly/monthly, исходные reset-сроки и отдельную строку качества/возраста.
При двух длинных окнах без 5h видны оба; сортировка предпочитает weekly.
Известные дробные остатки сортируются по возрастанию, неизвестные идут после них.
Окно monthly никогда не участвует в недельном среднем.

[Renderer](../../src/ui/rendering/popup.h) сохраняет окно 720×340, шаг карточки
124, две карточки в строке, Segoe UI, цвета/alpha и масштабирование DPI.
Внутренняя граница заголовка сдвинута для счётчика/процента; счётчик измеряется
по тексту, процент и * имеют отдельную область. Статус/возраст занимает нижнюю
строку карточки и не подменяет срок сброса. Длинные name/email сокращаются
многоточием в исходных областях. Без 5h длинное окно использует полную ширину.
Reset badge появляется только при count>0; неизвестный expiry скрывает только
отсчёт. Ровно семь дней ещё красные, больше семи — обычные.

[Popup window](../../src/ui/popup/window.h) сохраняет refresh, hover/press,
hit-test ссылок, outside-click, scroll и DPI. Пустой успешный пул отличим от
ожидания/ошибки. XAML recovery и соседний виджет не изменены. Время успеха
по-прежнему обновляется только по account-критерию, независимо от версий.

## Версии и lifecycle

[releases.h](../../src/versions/releases.h) читает только административные GET
`/system/version` и `/system/check-updates` через существующий envelope transport.
Текущая версия — `data.version`, taskbar-индикатор — достоверный `data.has_update`.
Непустой warning не считается успешной проверкой. Содержимое warning не выводится.
Одинаковый путь обслуживает полный и ограниченный ключ; префикс не проверяется.

Независимый GitHub GET читает опубликованные релизы `Wei-Shaw/sub2api`, включая
prerelease, исключая drafts. Выбирается старший SemVer среди 100 последних
релизов ответа API, без сортировки строками; beta.10 старше beta.9, stable старше
beta того же core. Пустой список/отсутствие распознаваемого SemVer — Unknown,
повреждённый ответ — Failed. Исходный tag сохраняется для ссылки, все reserved
символы кодируются как часть одного URL-сегмента. Ссылка мода отключена.

[presentation.h](../../src/versions/presentation.h) различает ожидание,
неизвестность, ошибку, rate limit, актуальность и доступное обновление.
Рамка ошибки/лимита красная, нового релиза зелёная, цвет текста обычный.
Ошибка текущей версии не превращается в «Нет новых версий».
GitHub не определяет taskbar-индикатор, тот виден и без пригодного среднего.
Пример: server has_update=true и GitHub 429 дают индикатор на taskbar и сообщение
о лимите GitHub в popup; аккаунты остаются доступны, время их успеха не меняется.

[Runtime](../../src/integration/runtime.h) владеет отдельным PTP_WORK версий,
не накапливает задания. Общий deadline аккаунтов сохранён. Два system GET имеют
свой суммарный budget 10 секунд, GitHub — 10 секунд после ожидания mutex.
Публикация аккаунтов/age timer не ждут версий. Cancel и generation проверяются
под общим mutex; settings/unload дожидаются версии до reset/закрытия event.

## Persistent cache и диагностика

[release_cache.h](../../src/versions/release_cache.h) использует отдельные
`LOCALAPPDATA/Sub2ApiTaskbarDashboard/github-releases-v1.json` и
`Global\Sub2ApiTaskbarDashboard.GitHubReleases.v1.<path-hash>`.
Mutex удерживается до завершения операции; ожидание ограничено 15 секундами
и прерывается cancel. Слот с часовым минимумом записывается до HTTP, затем
атомарно записывается итог. Отмена/исключение переводят Pending в Failed с
сохранением паузы. При аварийном завершении процесса Pending истекает по
nextCheckUtc; ошибка кеша запрещает обходной сетевой запрос.

Manual/reload не обходят минимум. 429 и 403 с Remaining=0, Retry-After или
сообщением rate limit/abuse получают RateLimited; обычный 403 — Failed.
Используется наиболее поздний часовой минимум, Reset+1 и Retry-After
(секунды или HTTP-date). Успех с Remaining=0 остаётся успехом с продлённой паузой.
Кеш содержит только tag/status/deadline. Ключ не передаётся в публичный GET.
Диагностика — короткие English events/status/HRESULT: без message/body,
заголовков, email и upstream IDs.

## Проверки и ограничения

[popup_versions.cpp](../../tests/popup_versions.cpp) вызывает production SemVer,
парсинг, policy, файловую cache transaction, UI-проекции и publication gate.
Фиктивные request/clock/stop не делают HTTP, не открывают UI или пользовательский
кеш. Тесты используют уникальный временный файл/mutex, два конкурирующих клиента,
проверяют отмену/исключения, повреждённый кеш, 403/429/Retry-After,
stable/prerelease, beta.9/beta.10, неизвестные данные, ссылки и Reset.
Часть геометрии проверяется production helpers; это не визуальная приёмка.

Fixtures добавлены, но не скомпилированы и не запущены. Статически прослежены
контракты сервера, зависимости, ownership/cancel/drain, account deadline,
границы UI-строк, авторизация, безопасные логи и независимость кеша.
Проверены 28 C++ файлов: все 26 production-файлов достижимы из mod.wh.cpp,
нет разрывов/циклов локальных includes и несбалансированных скобок после
исключения строк/комментариев. Проверены 68 текстовых файлов на UTF-8 и
повреждения текста, 135 локальных ссылок в 40 Markdown-файлах — цели существуют.
Это структурные проверки исходников, они не доказывают компиляцию.
Не подтверждены C++ сборка, выполнение fixtures, WinHTTP на реальных ответах,
межпроцессная работа в разных сессиях Windows, DPI/скриншоты, reload/unload,
XAML recovery и сосуществование модов. Этап 03 остаётся in-progress, этап 04 —
verification. Работа остановлена после реализации 04; этап 05 не начинался.
