# Виджет на нескольких мониторах

## Наблюдение и граница подтверждения

05.11.2026 пользователь сообщил: оба мода включены одновременно,
Codex LB виден на всех экранах, Sub2API — только на главном.
Оба исходника уже обходили основные и дополнительные taskbar HWND,
но их recovery повторно подключал XAML watcher только при отсутствии всех виджетов.
Восстановление обходило только ранее зарегистрированные XAML-корни.
Это оставляло частичное обнаружение панелей без повторного подключения.
Точная последовательность событий в Explorer пользователя не записана.

## Изменения реализации

- [windows.h](../../src/integration/windows.h) отдельно перечисляет
  `Shell_TrayWnd` и `Shell_SecondaryTrayWnd` текущего процесса. Эта же выборка
  используется для поиска дочерних XAML HWND и подсчёта ожидаемых виджетов.
- [widgets.h](../../src/ui/taskbar/widgets.h) регистрирует TaskbarFrame также
  по любому его дочернему элементу. Рамка определяется именем `TaskbarFrame`
  или runtime-классом `Taskbar.TaskbarFrame`. Чужой виджет может помочь найти
  рамку через предков, но не присваивается и не изменяется.
- Если рамка ещё не получила XamlRoot, сохраняется слабая ссылка на неё.
  Recovery читает её текущий XamlRoot на владеющем UI-потоке; раннее событие
  больше не теряет панель до следующего изменения дерева.
- Корни проверяются отдельно от потоков: один UI-поток может владеть несколькими
  панелями. Повторное сканирование одного корня и повторное обнаружение собственного
  виджета не создают копий; существующие события и положение обновляются.
- [runtime.h](../../src/integration/runtime.h) сначала восстанавливает известные
  панели, затем раз в пять секунд сравнивает число виджетов с числом taskbar HWND.
  При неполном количестве повторно подключает watcher, даже если главный экран
  уже работает. Диагностика `Taskbar widgets incomplete (N/M)` содержит только
  количества. Число дочерних HWND и число UI-потоков не подменяют число панелей.
- Освобождение слабых ссылок остаётся в существующем cleanup на UI-потоке.
  Сетевой опрос, независимые имена мода и позиция слева от Codex LB не менялись.

Например, при двух taskbar HWND и одном виджете прежнее условие `count == 0`
не срабатывало. Теперь после восстановления известных корней недостающая
панель вызывает повторное подключение watcher; после появления второго
виджета это условие перестаёт срабатывать.

## Проверка

Выполнен статический разбор обнаружения, позднего появления XamlRoot,
повторного сканирования, нескольких корней одного потока и очистки.
С разрешения пользователя выполнена проверка всей единицы трансляции
`mod.wh.cpp` установленным Windhawk clang++: `-fsyntax-only`, C++23,
target `x86_64-w64-mingw32`, `WH_MOD/WH_EDITING` и `windhawk_api.h`.
Рабочий каталог — `D:/Programs/Windhawk/Compiler`; код выхода 0,
диагностики компилятора нет. Бинарный файл не создавался, линковка не проверялась.
Тесты, Windhawk и Explorer для этой правки не запускались.
Результаты прежних проверок и syntax-check не подтверждают работу на мониторах.

После перекомпиляции мода в Windhawk требуется проверить:

1. При включённом показе панели задач на всех дисплеях Sub2API виден на каждом
   экране вместе с Codex LB; проценты обновляются, каждый виджет открывает popup.
2. Выключение и включение Sub2API при уже работающем Codex LB восстанавливает
   все виджеты и не создаёт дубликаты, в том числе после ожидания более пяти секунд.
3. Переподключение монитора, смена главного экрана и перестроение панели задач
   восстанавливают виджеты; положение рядом с Codex LB и DPI остаются корректными.

Правка не включает панели задач, отключённые в настройках Windows.
Закрытый первоначальный план и его историческая приёмка не изменены.
